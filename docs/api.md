# camera API reference

Every public declaration of the package, by module, with its comment from the source.
Generated by `tools/gen_api.py`; edit the comments in `src/`, not this file.

- [`<camera>`](#camera)

## `<camera>`

`<camera>`: photos for apps on eskiu-packages/ui. An app picks one from the photo library, takes
one with the system's camera, or shows the camera live in a CameraView and captures what it
shows. Each photo comes back as a JPEG file the app can show with Image: upright, at most
2048 pixels on its longer side, in the app's cache directory (a blob: URL on the web). On
macOS the live view, captures and frames work, but there is no system camera screen; on
Linux and Windows only the library works (an image file), and the camera is unavailable.

### PhotoStatus

```eskiu
enum PhotoStatus { PhotoReady, PhotoCancelled, PhotoDenied, PhotoUnavailable, PhotoFailed }
```

What a Photo reports: a photo is ready, the user cancelled, the camera permission is
denied, there is no camera (a simulator), or it failed.

### Photo

```eskiu
struct Photo { int status; string path; int width; int height; }
```

A photo, or why there is none. `path` is the file (borrowed for the handler's call: copy it
to keep it), `width` and `height` its size in pixels.

### camera_read

A message on the "camera" channel as a Photo. Its path points into `payload`.

### PhotoHandler

The latest render's handler, kept in the hook's slot.

### camera_release_handler

```eskiu
void camera_release_handler(escaping fn(Photo)->void handler)
```

Frees a photo handler's closure; use_photos calls it when it replaces or drops the

### use_photos

```eskiu
void use_photos(escaping fn(Photo)->void on_photo)
```

`on_photo` gets each photo (or failure) the camera, the picker or a capture hands back while
the scope is mounted. Mount one per screen: every mounted handler gets every photo.

### camera_supported

```eskiu
bool camera_supported()
```

Whether the device has a camera that CameraView, camera_capture and use_camera_frames can
show, known before one is mounted: false on the iOS simulator, a phone without a camera, a
browser without getUserMedia (a page not served over https), a Mac without a camera, Linux
and Windows. The photo
library (camera_pick_photo) does not need it. True does not mean the user allowed the
camera: that is asked when the first CameraView mounts.

### camera_pick_photo

```eskiu
void camera_pick_photo()
```

The system's photo picker: the user chooses one photo, or cancels.

### camera_take_photo

```eskiu
void camera_take_photo()
```

The system's camera: the user takes one photo, or cancels. PhotoUnavailable where there is
no camera or no system camera screen (a simulator, the native desktop hosts); a desktop
browser falls back to choosing a file.

### camera_capture

```eskiu
void camera_capture()
```

What the mounted CameraView shows now, as a photo.

### CameraView

```eskiu
void CameraView(Style style, bool front)
```

The camera, live, filling the box the layout gives it (cropped to it): the back camera, or
the front one when `front`. The first one mounted asks for the camera permission;
use_photos gets PhotoDenied or PhotoUnavailable when it cannot show it. A Mac's camera has
no side: both open the built-in camera (or the system's default); CameraDeviceView opens a
chosen one.

### CameraKind

```eskiu
enum CameraKind {
    CameraKindUnknown, CameraKindFront, CameraKindBack, CameraKindBuiltIn, CameraKindExternal,
    CameraKindContinuity, CameraKindDeskView
}
```

What kind of camera camera_devices lists: a phone's or tablet's front or back camera, a
computer's built-in one, an external one (USB), an iPhone used as a Mac's camera (Continuity
Camera), its Desk View, or one the platform does not say (the web).

### CameraDevice

```eskiu
struct CameraDevice { String id; String name; int kind; }
```

One camera: `id`, which CameraDeviceView opens (the platform's own: an AVCaptureDevice's
uniqueID, a Camera2 id, a browser's deviceId), the name the platform gives it, and its kind.

### camera_field

```eskiu
void camera_field(string text, *int at, *String out)
```

The text from `*at` up to a tab or the line's end, into `out`; `*at` goes past a tab, and
stays on a newline.

### camera_devices_parse

```eskiu
void camera_devices_parse(string text, List<CameraDevice>* out)
```

"KIND\tID\tNAME" lines as devices, into `out`. A line without an id is left out.

### camera_devices

```eskiu
void camera_devices(List<CameraDevice>* out)
```

The cameras CameraDeviceView can open, in the platform's order, into `out` (free them with
camera_devices_free). macOS lists built-in, external, Continuity and Desk View cameras; iOS
each lens (front, back, ultra wide, telephoto) and an iPad's external camera; Android every
Camera2 id with its facing; the web the browser's video inputs (their names and ids only
once the user allowed the camera, and none before the page has asked: list again after a
CameraView mounted). Empty on Linux and Windows, and where there is no camera.

### camera_devices_free

```eskiu
void camera_devices_free(List<CameraDevice>* devices)
```

Frees the ids and names camera_devices filled `devices` with, and the list.

### CameraDeviceView

```eskiu
void CameraDeviceView(Style style, string device_id)
```

The camera `device_id` (a CameraDevice's id) live, as CameraView shows its camera: frames,
captures and the permission work the same. An id the platform does not have (a camera
unplugged since it was listed) gives use_photos PhotoUnavailable; "" opens CameraView's
back camera.

### CameraFormat

```eskiu
enum CameraFormat { CameraNV12, CameraNV21, CameraI420, CameraYUV420, CameraRGBA }
```

How a frame's pixels are laid out. NV12: a Y plane, then one plane of interleaved U and V
(U first). NV21: the same with V first. I420: Y, U and V planes, chroma a quarter of the
size. YUV420: Y, U and V planes whose chroma samples are `pixel_stride` bytes apart. RGBA:
one plane of 4 bytes a pixel (the web).

### CameraMatrix

```eskiu
enum CameraMatrix { CameraBT601, CameraBT709 }
```

The matrix a frame's YUV is encoded with: BT.601 (standard definition, JPEG) or BT.709 (HD).

### CameraPlane

```eskiu
struct CameraPlane { *uint8 data; int row_stride; int pixel_stride; int64 size; }
```

One plane of a frame: `data` (borrowed for the handler's call), the bytes from one row to
the next, from one sample to the next in a row (2 in NV12 and NV21's chroma plane, from one
U to the next), and the bytes readable from `data`.

### CameraFrame

```eskiu
struct CameraFrame {
    int width;
    int height;
    int format;
    int plane_count;
    CameraPlane[3] planes;
    int rotation;
    int64 timestamp_ns;
    bool front;
    int matrix;
    bool full_range;
}
```

A frame as the sensor sees it. `width` and `height` are in pixels; `plane_count` planes are
set, as `format` says. `rotation` (0, 90, 180 or 270) is how far to turn it clockwise to be
upright as the screen is held; `timestamp_ns` is the platform's capture time (a monotonic
clock, for spacing frames); `front` is the front camera, whose frames are not mirrored;
`matrix` and `full_range` say how its YUV maps to RGB.

### CameraFrameOptions

```eskiu
struct CameraFrameOptions {
    int width = 1280;
    int height = 720;
    int fps = 30;
}
```

What use_camera_frames asks for: the frame size (the platform picks the nearest it has,
landscape, as the sensor gives it) and at most `fps` frames a second.

### CAMERA_FRAME_INFO

```eskiu
const int CAMERA_FRAME_INFO = 24;
```

How many int64 values camera_native_frame_acquire fills: width, height, format,
plane_count, rotation, front, matrix, full_range, timestamp_ns, then for each of 3 planes
its data pointer, row_stride, pixel_stride and size.

### camera_frame_read

```eskiu
bool camera_frame_read(*int64 info, *CameraFrame out)
```

The values camera_native_frame_acquire filled, checked, as a frame; false when they do not
describe one (unknown format, a missing plane, strides or sizes that do not cover the
pixels), so a handler never reads outside a buffer.

```eskiu
void camera_release_frame_handler(escaping fn(*CameraFrame)->void handler)
```


Borrows the latest frame from the platform, hands it to `handler` and gives it back.

### use_camera_frames

```eskiu
void use_camera_frames(CameraFrameOptions options, escaping fn(*CameraFrame)->void on_frame)
```

`on_frame` gets the mounted CameraView's frames while the scope is mounted, on the UI
thread; the frame and its planes are borrowed for the call (convert or copy what you keep).
Keep it short: the UI waits while it runs. A full-size conversion (to_rgba of a 1080p frame
is two million pixels) or a model's inference belongs on a worker thread: copy the frame
there with copy_to (docs/frames.md), or ask for a smaller size.
A frame that arrives while it runs replaces the one waiting: a slow handler gets fewer,
newer frames, never a queue. A CameraView must be mounted for frames to come (it may be
small); new options are applied when they change.

### CameraFrameCopy

```eskiu
struct CameraFrameCopy { CameraFrame frame; *uint8 data; int64 capacity; }
```

An owned copy of a frame, to work on outside the handler (another thread, a later frame):
`frame` describes the copy, its planes pointing into `data`, which is kept and grown from
one copy to the next so copying each frame allocates nothing once warm. Free it with
CameraFrameCopy_free. docs/frames.md has the pattern for a worker thread.

### CameraFrame_copy_to

```eskiu
bool CameraFrame_copy_to(*CameraFrame self, *CameraFrameCopy out)
```

`self`'s planes copied into `out` (one memcpy a plane: about 3 MB for a 1080p NV12 frame,
far less than converting it), so `out.frame` stays valid after the handler returns. False
when the buffer could not grow (out keeps its last copy).

### CameraFrameCopy_free

```eskiu
void CameraFrameCopy_free(*CameraFrameCopy self)
```

Frees the copy's buffer; the copy is empty after (copy_to may fill it again).

### CameraYuvCoeffs

```eskiu
struct CameraYuvCoeffs { int y_offset; int y_scale; int v_r; int u_g; int v_g; int u_b; }
```

The fixed-point (1 << 16) coefficients that turn one matrix and range's YUV into RGB.

### camera_yuv_coeffs

```eskiu
CameraYuvCoeffs camera_yuv_coeffs(int matrix, bool full_range)
```

The coefficients for `matrix` (a CameraMatrix), full range (Y 0-255, chroma 0-255 about
128) or limited (Y 16-235, chroma 16-240).

### camera_clamp8

```eskiu
uint8 camera_clamp8(int value)
```

A fixed-point value rounded to 0-255.

### camera_yuv_to_rgb

```eskiu
void camera_yuv_to_rgb(*CameraYuvCoeffs c, int y, int u, int v, *uint8 rgb)
```

One pixel's Y, U (Cb) and V (Cr) as R, G and B into `rgb[0..2]`.

### CameraFrame_out_width

```eskiu
int CameraFrame_out_width(*CameraFrame self, bool upright)
```

The frame's width once turned upright (to_rgba with `upright`), or as it is.

### CameraFrame_out_height

```eskiu
int CameraFrame_out_height(*CameraFrame self, bool upright)
```

The frame's height once turned upright, or as it is.

### CameraFrame_to_rgba

```eskiu
void CameraFrame_to_rgba(*CameraFrame self, *uint8 out, int out_stride, bool upright)
```

The frame as RGBA (alpha 255) into `out`, `out_stride` bytes a row, with its own matrix
and range; turned by its rotation when `upright` (out_width and out_height give the size
`out` needs). Pure Eskiu, on the calling thread.
